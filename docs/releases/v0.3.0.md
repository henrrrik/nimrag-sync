A safer sync.

## Fixed

- **Nothing is cleared that cannot be written back.** Every line a sync writes is checked against what the
  inReach takes before anything on it is cleared; the waypoints and routes are checked before their tables
  are. Before, one quick text too long for the device could stop a sync after it had cleared the presets and
  quick texts.
- **What Garmin sends nothing for stays.** When Garmin's service has a list of contacts but none of the
  quick texts or presets, the sync clears the device's sync data all the same (as inReach Sync does), and
  then writes the device's own quick texts and presets back. Before, they were lost.
- **One nimrag-sync at a time on a device.** The window, a second window and the command line no longer
  talk to the inReach at once and take each other's answers: each waits up to 10 seconds for the device,
  then says it is busy, and a preview or sync keeps it for its whole run.
- **The same inReach, start to end.** After asking Garmin's service, the sync writes only if the device is
  still on and is the one it read; swapping devices mid-sync stops it before any write.
- **Closing the window during a sync or an update** waits for it to finish instead of crashing; a sync
  stopped half-way would leave the inReach half-written.
- An answer from Garmin without its list of waypoints or routes stops the sync, rather than clearing them
  from the device.
- The account's password goes only to an HTTPS sync server.
- Settings with quotes in them are written as they are.
- A preset too long for the inReach still loses its last recipients to fit, but the preview now says whom.
- A backup never overwrites another made in the same second.
- A software update larger than an inReach's software can be is refused before it is downloaded.
- After an update, the next inReach plugged in gets its own update check.

Tried on an inReach Mini: two previews at once (the second says the device is busy) and a full sync.

## Install

Arch Linux and Omarchy, x86_64 and aarch64. The packages are signed with nimrag-sync's release key (B115 52BD 4C4A C502 17E3  DF95 4B81 8981 13EB C4F6). Have pacman trust it once:

```sh
curl -sL https://github.com/henrrrik/nimrag-sync/releases/download/v0.3.0/nimrag-sync.asc | sudo pacman-key --add -
sudo pacman-key --finger B11552BD4C4AC50217E3DF954B81898113EBC4F6    # check: B115 52BD 4C4A C502 17E3  DF95 4B81 8981 13EB C4F6
sudo pacman-key --lsign-key B11552BD4C4AC50217E3DF954B81898113EBC4F6
```

Then pacman installs a package straight from its address, checking its signature:

```sh
sudo pacman -U https://github.com/henrrrik/nimrag-sync/releases/download/v0.3.0/nimrag-sync-0.3.0-1-x86_64.pkg.tar.zst
```

(`aarch64` in place of `x86_64` on ARM.) Without the key, download the package and `SHA256SUMS`, check
with `sha256sum --ignore-missing -c SHA256SUMS`, and `sudo pacman -U` the file.
